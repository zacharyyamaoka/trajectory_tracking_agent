# O4.8 Holdout is reporting only

## Requirement

> **Holdout** is scored only by `evaluate(..., split="holdout")` for reporting. Choosing between solutions on holdout
> is a bug (it would make holdout a second dev set). The leaderboard shows holdout − dev beside each admissible solution.

From [OBJECTIVES.md §4 The score](../OBJECTIVES.md#4-the-score), ruler v1. OBJECTIVES.md is the frozen ruler and the one source of every number; this note explains it and never overrides it.

## What it means

The holdout tasks never run in a dev evaluation, and no solution reads them ([O1.2](O1.2-what-a-solution-may-know.md)).
An agent scores holdout only to report a finished solution, and never picks between solutions by it. The leaderboard
puts holdout − dev beside each admissible solution, so a dev gain that does not carry to unseen tasks shows.

## Why

"It would make holdout a second dev set" (OBJECTIVES.md §4): once a choice reads holdout, it stops being unseen.

## How it is checked

- `test_holdout_is_never_scored_by_a_dev_evaluation`: the dev split holds only dev tasks and shares none with holdout.

That test checks the splits, not the agent. That no agent selects on holdout is a rule in AGENTS.md ("Never select on
holdout"), which the dispatcher reads for in each solution's change and lineage.
