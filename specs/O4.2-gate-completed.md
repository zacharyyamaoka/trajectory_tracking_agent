# O4.2 Gate: completed

## Requirement

> | `completed` | no exception, no NaN command, the run reaches the trajectory's end and settles | a crash is not a score |

From [OBJECTIVES.md §4 The score](../OBJECTIVES.md#4-the-score), ruler v1. OBJECTIVES.md is the frozen ruler and the one source of every number; this note explains it and never overrides it.

## What it means

The run has to finish cleanly. In `evaluate.py`'s words: the build and every tick raise nothing, no command field
that drives torque is NaN or infinite, the host loop logs no abort and the physics does not diverge, the task stays
inside its wall-time box (CONTRACT §4), the run reaches the trajectory's end with finite joints, and it settles: every
tool error over the trajectory's last 0.1 s is within Zach's 1 mm band (`SETTLE_BAND_MM`, the same band as
[O4.3](O4.3-gate-stop-error.md)).

## Why

"A crash is not a score" (OBJECTIVES.md §4). A controller that blew up halfway would otherwise be scored on the samples
it did run, and could look good doing it. The settle band is Zach's 1 mm tool gate again:
[a 1 mm tool gate](../feedback/2026-11-11-tool-gate-1mm.md).

## How it is checked

- `test_gate_completed`: the gate reads the `completed` flag and fails closed.
- `test_a_build_that_raises_fails_every_gate`: a `build` that raises fails `completed` and every other gate.
- `test_a_nan_command_fails_completed`: a NaN in a torque-driving command field fails it.
- `test_the_time_box_fails_completed`: a controller too slow for its wall-time box fails it.
