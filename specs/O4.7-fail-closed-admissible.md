# O4.7 Fail closed, admissible

## Requirement

> **Gates (per task; a solution is *admissible* only if every dev task passes every gate):**
>
> **Every verdict fails closed** (arm_motion_bench v3.11): a missing or NaN value is a failed gate, never a pass.

From [OBJECTIVES.md §4 The score](../OBJECTIVES.md#4-the-score), ruler v1. OBJECTIVES.md is the frozen ruler and the one source of every number; this note explains it and never overrides it.

## What it means

A gate whose value is missing or NaN has failed. A solution is admissible only when every dev task passes all five
gates ([O4.2](O4.2-gate-completed.md) to [O4.6](O4.6-gate-floor-clearance.md)); with no tasks, it is not admissible.
Only admissible solutions can be the best ([O4.9](O4.9-ranking.md)).

## Why

Fail closed comes from arm_motion_bench v3.11 (OBJECTIVES.md §4). A reading of why: a gate that passes on missing data
passes exactly the runs that broke worst, since a crash produces no numbers.

## How it is checked

- `test_gate_verdicts_*`: every gate fails on a missing or NaN value and passes on good values.
- `test_gates_tuple_is_frozen`: the five gates, by name and order.
- `test_admissible_*`: every task and every gate; one failure, a task missing a gate, or no tasks at all is not
  admissible.
- `test_rows_from_a_failed_task_are_json_safe`: a crashed task's row still records failed verdicts.
