# Physical tracking evidence

[`audit_archives.py`](audit_archives.py) reads the saved physical traces with the bench's frozen dataset loader. For each highest-rung task it compares the clock, joint positions, velocities and accelerations, and TCP references against the immutable tape before calculating either performance metric. It scores only the prescribed tape, including the holds already on that tape. Additional run-out is beyond that measurement interval.

The [archive evidence](archive-evidence.json) is an encoder-FK diagnostic. The CAN 11 source logs board replies on the command clock. It has no independent calibrated measurement of the tip or acquisition timestamp on the load side. The highest-rung BAM FB legacy recording has 257 exchanges on its command clock, a median exchange interval of 17.012 ms, and an overspeed event. Its command clock and target coverage differ from the immutable 100 Hz tape.

Run it with the arm_motion_bench Python environment and provide the checkout as the first argument. The optional `--legacy-bam` takes the imported workspace trace and its original raw-run directory. The script reads stored data and has no hardware entry point.

[`camera_sampling.py`](camera_sampling.py) tests timing separately from camera pose accuracy. It resamples each of the 52 frozen CAN 11 trajectories at four frame phases, then linearly reconstructs the original 100 Hz positions from ideal, timestamped camera samples. The [result](camera-sampling-evidence.json) shows worst full-trace error of 2.640 mm at the original archive's native 15 Hz, 0.673 mm at 30 Hz and 0.181 mm at 60 Hz. The archived preview clip is transcoded to 30 Hz. The test uses noiseless positions and exact timestamps, so it does not validate an optical measurement or a frame-rate requirement by itself.

The archived runner's [device-free preflight](pendulum-preflight.json) accepted every step of the historical CAN 11 `ff_model` plans at rung 0.1 and both rung-1.0 splits. It estimated 812 seconds for the low-speed dev plan and 216 seconds total for the two top-rung plans, with three repeats per split. This test exercised the archived plans and the archived checker. The current rig needs its own released owner window, controller admission and calibrated, timestamped load-side measurement. The existing 15 Hz MP4 is a preview.

[`bam_fb_speed_preflight.py`](bam_fb_speed_preflight.py) calls the stock file-only BAM FB speed checker on the frozen reference samples. Under bench contract v3.14, all [86 existing rung-0.25 tapes](bam-fb-speed-preflight.json) passed the tape speed check, and all 118 rung-1.0 tapes were refused because of the 0.25 fraction cap. The available conveyor tapes at 0.25 cover the 32 static-belt routes. The 32 moving-belt routes need fresh intercept timing for the admitted rung and measured belt clock. This checks the reference speeds only. The stock preflight still has to inspect the actual controller bundle and the run's recorded joint speeds.

In a [four-path nominal simulation pilot](bam-fb-capped-sim-pilot.json) at rung 0.25, the unchanged full-speed controller passed all existing checks and every stop target. The two workspace paths reached 1.474 mm and 1.159 mm RMS. Both static-belt paths stayed below 0.685 mm RMS. The capped workspace calls for its own confirmation and a low-speed friction fit before a controller locks for the real bench.
